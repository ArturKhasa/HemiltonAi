# Офлайн-прогон моделей на боевых диалогах

Отвечает на вопрос «подходит ли нам модель» без риска для живых клиентов.

Как это работает. Каждый боевой прогон сохраняет в `ai_runs.full_context` ровно
то, что уходило модели: системный промпт и всю историю хода вместе с вызовами
инструментов и их ответами. Берём этот контекст, отрезаем финальный ответ,
подменяем системный промпт на текущий — и просим модель-кандидата написать ответ
заново. Дальше считаем нарушения теми же проверками, которыми их ловит `runner`
на бою: `hedges_delivery_price`, `promises_both_gifts`, `reply_advances_funnel`,
`asks_confirmation` и остальные.

Инструменты кандидат не вызывает — он видит ответы инструментов из записи. Это
и нужно: сравниваем, что модели пишут, имея на руках одни и те же доказательства.

## Запуск

```bash
docker run -i --rm \
  -e DATABASE_URL="$(grep '^DATABASE_URL=' .env | cut -d= -f2-)" \
  -e OPENAI_API_KEY="$(grep '^OPENAI_API_KEY=' .env | cut -d= -f2-)" \
  -v "$PWD":/src -v /tmp/empty.env:/src/.env -w /src hemiltonai-app \
  python docs/eval/fetch_cases.py
```

Собирает боевые ходы в `.eval/cases.json` и раскладывает по классам: отказ,
переспрос, правка дизайна, сверка подряд, обычный ход.

```bash
docker run -i --rm \
  -e DATABASE_URL="..." -e OPENAI_API_KEY="..." \
  -v "$PWD":/src -v /tmp/empty.env:/src/.env -w /src hemiltonai-app \
  python docs/eval/run_eval.py gpt-5.6-luna,gpt-5.6-sol,gpt-5.6-terra 12
```

Первый аргумент — модели через запятую, второй — сколько ходов брать на класс
(редких классов берётся втрое больше). `EVAL_DUMP=1` печатает реплики, на которых
сработали проверки.

Прогон на 95 ходах — примерно 1,2 млн входных токенов на модель, 5-7 минут.

## Результат прогона 23.08.2026

| | luna | sol | terra |
|---|---|---|---|
| нарушений на ход | **0.35** | 0.38 | 0.38 |
| скрипт указан | 51/95 | 54/95 | 56/95 |
| средняя уверенность | 0.96 | 0.95 | 0.93 |
| валидный JSON | 84/95 | 94/95 | 91/95 |
| среднее время ответа | 5.1 с | 6.1 с | 4.2 с |

Разницы между тремя ступенями линейки нет: дорогие ведут себя чуть хуже дешёвой.
Главное нарушение у всех трёх одно и то же — «Супер, зафиксировала» в ответ на
реплику, где фиксировать нечего. Лечится это воротами в коде, а не выбором
модели.

Цена вопроса при этом разная на порядок. Тарифы за 1M токенов (короткий контекст):

| | вход | вход из кэша | выход | во сколько раз дороже luna |
|---|---|---|---|---|
| gpt-5.6-luna | $0.20 | $0.02 | $1.20 | — |
| gpt-5.6-terra | $2.00 | $0.20 | $12.00 | 10× |
| gpt-5.6-sol | $4.00 | $0.40 | $20.00 | 20× |

Что это значит на нашем трафике: день 21 августа (150 лидов, 1 242 прогона) на
luna стоил $2.02, на terra стоил бы $20, на sol — $40. На полном трафике в 2 500
лидов в день это $1 000, $10 100 и $19 800 в месяц соответственно.

Сам прогон обошёлся в $8.74 без учёта кэша: luna $0.40, terra $2.61, sol $5.73.


## Помогли ли правки — прогон 23.08 (luna, 95 ходов)

Три варианта на одних и тех же боевых ходах. «Шаг не закрыт» — 47 ходов, где
клиент отказался, переспросил или попросил правку, и фиксировать нечего.

| | похвала на незакрытом шаге | нарушений на ход |
|---|---|---|
| A — как было | **19 из 47** | 0.43 |
| B — только новое условие скрипта | 19 из 47 | 0.43 |
| C — условие + скрипт скрыт кодом | **0 из 47** | 0.47 |

Правка в панели сама по себе (вариант B) не дала ничего: модель читает условие
«применяй ВСЕГДА» и не читает оговорку. Работают только ворота в коде.

Побочный эффект варианта C виден там же: без готового скрипта модель пишет ответ
сама и чаще забывает закрыть его вопросом (6 → 21 из 95). На бою это ловит гейт
`no_question` и гонит прогон заново, то есть клиент этого не увидит — но каждый
такой ход стоит лишнего вызова модели.

Остаточное «двигает воронку на отказе» (13 из 47) — это когда модель пишет
«Супер, зафиксировала» своими словами, без скрипта. Ловится гейтом
`ignores_refusal`, дальше диалог уходит куратору.
